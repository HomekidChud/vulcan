# Self-hosting: Vulcan compiles itself

Since v1.11 the compiler is written in Vulcan. `self/vulc.vulcan` (~3,100
lines) is a complete front-to-back compiler for **Vulcan Core** — the stable
subset of the language described below — and it emits the same C dialect as
the original Rust compiler.

## The bootstrap chain

```
stage 0  the Rust compiler in this repo (src/*.rs)   — bootstrap seed
stage 1  vulc built by stage 0   (Rust -> C -> binary)
stage 2  vulc built by stage 1   (vulc -> C -> binary)
stage 3  vulc built by stage 2   (output only, for the fixpoint check)
```

`vulcan bootstrap` runs the whole chain and asserts that **stage2.c and
stage3.c are byte-identical** — the compiler, compiled by itself, reproduces
itself exactly. This is the same fixpoint verification rustc performs on its
stage2/stage3 artifacts, and Go has used since 1.5 when the compiler was
rewritten from C in Go.

After stage 1 exists, the Rust compiler is not needed to build the compiler
from source: stage 1 compiles `vulc.vulcan`, forever.

## Commands

| command | what it does |
|---|---|
| `vulcan bootstrap` | run the full chain + fixpoint check + smoke test |
| `vulcan self <file>` | compile + run a program with the self-hosted compiler |
| `./scripts/self-test.sh` | every `self/test/*.vulcan` must produce identical output on both compilers |

Artifacts land in `target/self/`. The stage-1 binary is rebuilt automatically
whenever `self/vulc.vulcan` changes.

## Vulcan Core (the subset vulc compiles)

- **Items**: `fn`, `struct`, `impl`, `const`
- **Types**: `i64`, `f64`, `bool`, `string`, `void`, user structs, one-dimensional `[T]` arrays
- **Statements**: `let` (with optional `: [T]` annotation), `=` / `+=` / `-=` / `*=` / `/=` / `%=`, `if` / `elif` / `else`, `while`, `for i in a..b` / `a..=b`, `for x in arr`, `return` / `break` / `continue`, expression statements
- **Expressions**: literals, casts (`as i64` / `as f64`), struct literals (`Point { x: 1.0, y: 2.0 }`), array literals, method calls, field access, indexing, arithmetic / comparison / logical operators
- **Builtins**: `print`, `to_string`, `to_int`, `to_float`, `char_at`, `len`, `arg_count`, `arg`, `file_read`, `file_write`, `file_exists`, `exit`, `sleep_ms`, `clock`, `ms_now`, `input`, `rand_int`
- **Methods**: array (`push` `pop` `shift` `last` `contains` `insert` `remove` `join`) and string (`len` `upper` `lower` `trim` `contains` `find` `substring` `split` `replace` `repeat` `starts_with` `ends_with`)

## Architecture notes

- **Arena AST with integer indices.** Every arena (`exprs`, `stmts`, `fns`, ...)
  is a `[T]` array with a dummy element at index 0, so real data starts at 1
  and index 0 doubles as "none".
- **`blk` arena for statement ranges.** Because a statement with a body is
  allocated *before* its body is parsed (so the parent's index range stays
  meaningful), block children are collected locally and appended to a
  dedicated `blk` arena contiguously. The same collect-then-append pattern is
  used for call/method arguments (`iargs`) and struct-literal field inits
  (`finits`), since nested expressions interleave in those arenas too.
- **`Ctx` is passed by value, copy-in / copy-out.** Every mutating function
  takes `Ctx`, returns `Ctx`, and callers reassign `c = f(c)`. Structs copy by
  value and arrays share data, so this is cheap (the Ctx struct itself is a
  handful of Vec headers).
- **Name-keyword safety.** User names that collide with C keywords or prelude
  helpers are renamed with a `vu_` prefix, mirroring the Rust compiler's
  `safe_name`.
- **The prelude is embedded** as a `const VPRELUDE` string in the source,
  regenerated by `scripts/gen-self-prelude.py` from the Rust compiler's own
  prelude emission, and re-emitted verbatim at the top of every output file.
