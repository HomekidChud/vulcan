# Vulcan — TODO / Roadmap

Working notes for future sessions. Everything here is ordered by impact and
effort. Verify with `cargo build --release && VULCAN_CC=gcc ./target/release/vulcan selftest`
after every change — all 24 cases must pass byte-identically on C, JS, and
Python backends before pushing.

## Current state (v1.10.0)

Phase 0 of the mega-upgrade (see docs/baseline.md) is done: versions
reconciled to Cargo.toml as the single source of truth (`vulcan --version`),
README history moved to CHANGELOG.md, the pkg.rs path-traversal and
git-clone-option-injection bugs fixed, lexer literals no longer silently
overflow, process-spawn failures print clean errors, and cargo test unit
tests (lexer, parser, pkg) run in CI next to selftest on both gcc and clang.

- Language: structs, enums, impl methods, match, f-strings, defer, FFI
  (`extern "c"` + `link`), nested arrays `[[T]]` (scalar bases in struct
  fields; any base as locals/params/returns), math builtins incl. `atan2`,
  `clamp`, `lerp`, `sign`, method calls on ANY expression receiver
  (`a.add(b).add(b)`, `get_pos(e).add(v)`, `pts[0].add(b)`), and
  forward references between functions (any-order `fn` calls, C backend
  now emits prototypes).
- Backends: C (native, hardened), JS (Node), Python 3 — byte-identical
  output, including method receivers on temporaries (JS/Py clone the
  receiver so mutating methods match C's value semantics).
- Libs: `lib/physics.vulcan` (2D rigid bodies), `lib/render3d.vulcan`
  (Vec3, camera, software 3D), `lib/engine.vulcan` (**Engine v0.3**:
  entities, scene, heightmap terrain + `terrain_sines` procedural
  islands, ray-sphere/ray-AABB + `scene_raycast` line-of-sight,
  `scene_shoot` hitscan, `scene_fire_projectile` with swept-impact
  anti-tunneling test, `bot_think` wander/chase/attack AI with steering,
  player controller, HUD, fixed-timestep loop, meshes with flat shading,
  first-person/orbit/spectator/third-person cameras, particles, weapons with
  ammo/reload, save/load level format, **v0.4**: 2x2 supersampled
  antialiasing + vignette in ALL backends (512x288 render, 256x144 resolve),
  day/night cycle (`sky_colors`, `sun_light`), distance fog (`fog_mix`),
  animated sea (`sea_color`), sky gradient (`draw_sky_gradient`), heading
  compass (`hud_compass`), pickups (`scene_spawn_pickup`), `mouse_dx/dy`
  builtins with web pointer-lock mouse look).
- Tooling: IDE, package manager, `vulcan test`, `vulcan package`
  (web/desktop/android/ios/mobile/native bundles — ALL generated by the
  toolchain itself: Gradle project + WebView activity for Android, Xcode
  project + WKWebView delegate for iOS, C webview shell for desktop. No
  Electron, no Capacitor, no npm), selftest (24 cases). `vulcan doc` + GitHub Actions CI.

## Compiler / language (highest impact first)

- [x] ~~Method calls on non-variable receivers~~ — DONE in v1.5 (temp
      materialization on C; `__vclone`/`_vclone` on JS/Py for semantic
      parity). Covered by selftest "method calls on expressions".
- [x] ~~Forward references between functions~~ — DONE in v1.5 (C backend
      emits prototypes before definitions; any-order fn calls work on
      all backends). Covered by selftest case.
- [x] ~~String comparison `==`/`!=`~~ — was already working; stale item.
      (Kept a selftest guard via the string cases.)
- [ ] **Nested arrays of structs as struct fields** — `struct W { grid: [[Cell]] }`
      panics with a clear message today. Needs Vec_Point emitted before
      Vec_Vec_Point in the struct-emission loop (see the panic in
      `generate_inner` field scan). Grids of scalars already work.
- [x] ~~Reference parameters~~ — DONE (Phase 1): `&T`/`&mut T` params,
      `&`/`&mut` call arguments, forwarding, pointee copy on let/match,
      method calls on ref receivers; semantics in DECISIONS.md. Selftest
      case 31. Gated (clear errors): non-struct refs, returning refs,
      ref locals, reassigning refs.
- [ ] **Closures / function values** — the biggest language gap. Start with
      non-capturing function pointers (`let f: fn(i64) -> i64 = double`), then
      closures over immutable locals. Needs parser (new Expr arm), all three
      backends, and a selftest case.
- [ ] **Struct copy on assignment for JS/Py** — the deepest semantic gap:
      JS/Py backends share struct objects by reference, so `let muzzle =
      e.pos` then mutating `e` also moves `muzzle` (C copies by value).
      Engine code now defensively copies at choke points (`scene_spawn`,
      `scene_fire_projectile`), but the real fix is deep-copy on struct
      assignment/passing in codegen_js/codegen_py. Big change; must keep
      all 24 selftest cases byte-identical.
- [ ] **`elif`-style `when` guards in match arms** and destructuring struct
      patterns in match (plain guards are DONE, Phase 1).
- [x] ~~Compile-time constant folding~~ — DONE (Phase 1): `fold_const` in the
      parser folds const int/float/bool/string expressions at compile time;
      refuses to fold division by zero so the runtime check still fires.
- [x] ~~Better errors~~ — DONE (Phase 1): `vulcan check <file>` collects all
      errors (lexer diagnostics, duplicate decls, type mismatches) with
      line/col + caret rendering instead of aborting on the first.
- [x] ~~String builder~~ — DONE (Phase 1): `lib/strbuf.vulcan` (StrBuf with
      push/push_num/build/build_sep, backed by a parts array + join).
- [x] ~~Struct copy on assignment for JS/Py~~ — DONE (Phase 1): `__sclone`/
      `_sclone` deep-copy structs (share arrays, matching C headers) at
      let/assign/call/return/element-store/field-store; selftest-guarded.
- [x] ~~Smaller int/float types~~ — DONE (Phase 1): i8/i16/i32/u8/u16/u32/f32
      on all three backends; arithmetic computes wide and wraps at storage;
      semantics recorded in DECISIONS.md.
- [x] ~~Match guards~~ — DONE (Phase 1): `when pats if cond`.
- [x] ~~Checked division~~ — DONE (Phase 1): / and % by zero abort with the
      same message/exit code on C, JS and Python.
- [x] ~~String replace/join~~ — DONE (Phase 1): literal replace (empty
      pattern = no-op) and [string].join on all backends.
- [x] ~~Payload enums / Option / Result / `?`~~ — DONE (Phase 1): variants
      with payloads (tagged structs), Option/Result construction +
      matching, `?` propagation, payload bindings usable in guards;
      semantics recorded in DECISIONS.md. Selftest case 30. Known gaps,
      all gated with clear compile errors (pick up here):
  - [ ] Arrays of payload enums / Option / Result (default_val gate).
  - [ ] Printing a payload enum directly (print must match-and-print).
  - [ ] `==` on payload enums (C has no struct equality).
  - [ ] `?` inside expressions (currently statement position via let).
- [ ] **Tail calls / deep recursion safety** — C backend overflows the stack
      on deep recursion; consider a stack-depth check or trampoline for
      self-tail-calls.
- [ ] **Bitwise ops on enums** — treat enums as flags (`|`/`&`/`^` already
      emit on i64 via `__bor` etc. on JS; make the type checker accept
      enum-typed operands).

## Roadmap: what "compete with Unity/Unreal" actually requires

Unity and Unreal are decades of engineering: GPU renderers, editors,
asset pipelines, networking, and huge ecosystems. Nobody closes that in
one repo. The honest plan is phases, each shippable on its own:

### Phase 1 — software renderer polish (v0.4, DONE)
- [x] ~~Antialiasing~~ — 2x2 supersampling in all three backends,
      byte-identical resolve (selftest-guarded).
- [x] ~~Day/night cycle, fog, animated water, sky gradient~~ — v0.4.
- [x] ~~Third-person camera + web mouse look~~ — v0.4.

### Phase 2 — rendering depth (next 1-3 sessions)
- [ ] **Textures on triangles** — per-face color + checker/noise
      procedural textures; then bitmap textures via `file_read` (BMP/PPM
      first, no external deps).
- [ ] **Shadows** — blob shadows (cheap, one quad) then a single
      directional shadow pass (project terrain silhouettes to a depth
      map, sample when shading).
- [ ] **LOD terrain** — far cells merge into bigger quads; keeps the
      20x20 grid fast at 64x64 and beyond.
- [ ] **MSAA 4x option** — supersampling is 4x fill cost; edge-only
      MSAA at tri boundaries would halve it.
- [ ] **Sprite/billboard entities** — camera-facing quads with alpha,
      for trees/particles at distance.

### Phase 3 — engine systems (sessions 4-8)
- [ ] **Animation component** — keyframed transform tracks on entities
      (position/rotation/scale curves), driven by scene time.
- [ ] **2D physics integration** — bolt `lib/physics.vulcan` bodies to
      entities (they currently only do gravity + terrain rest).
- [ ] **Slope collision + step-up** — finite-difference terrain gradient,
      wall push-out, slope sliding.
- [ ] **A\* pathfinding** over the terrain grid; bots route around water.
- [ ] **Audio via FFI** — miniaudio: `sound_play(name, vol, pitch)`,
      no-op stubs on JS/Py (like the graphics builtins).
- [ ] **Inventory + items** — pickup -> inventory -> equip/use flow on
      top of `scene_spawn_pickup`.
- [ ] **UI toolkit** — anchored panels, buttons, text wrapping, built on
      draw_rect/draw_text; enough for menus and a lobby.

### Phase 4 — GPU rendering (the real leap)
- [ ] **Raylib binding layer** (`lib/raylib.vulcan`) — `extern "c"` +
      `link "raylib"`: real GPU triangles, textures, shaders, models.
      Software renderer stays as the portable fallback (web/IDE).
- [ ] **WebGL2 output for web bundles** — the worker already posts
      frames; post draw lists instead and render on the page GPU.
- [ ] **Asset pipeline** — load meshes/textures from the package fs
      into engine types.

### Phase 5 — platform & shipping
- [x] **Mobile touch controls** — DONE in v1.8: every web bundle now
      has a virtual joystick + look-drag + FIRE/JUMP buttons on touch
      devices. The web link itself runs on phones.
- [x] **Vulcan-owned packaging** — DONE in v1.9: `vulcan package
      --platform android` generates a complete Gradle project (our own
      WebView activity, no Capacitor); `--platform ios` generates a
      complete Xcode project (our own WKWebView delegate, no CocoaPods);
      `--platform desktop` generates a C webview shell (no Electron).
      APK still needs the Android SDK + gradle on a real machine, but the
      project is 100% ours.
- [ ] **Android APK** — `vulcan package --platform mobile` scaffold
      exists; needs Capacitor + Android SDK on a real machine, then
      `./gradlew assembleDebug` produces the APK. Document the exact
      steps in README once tested on hardware.
- [ ] **Desktop binaries** — the Electron desktop bundle works today;
      add a pure-native window (SDL) path.
- [ ] ** itch.io / web publishing** — the single-file web bundle is
      already drop-in for itch.io uploads.

### Phase 6 — the game (private repo: vulcan-royale)
See the section at the bottom. The engine phases above are its
prerequisites.

## Performance path to "beat C++" (realistic framing)

Vulcan compiles through C, so "beating C++" really means: C-level speed
with a safer, more productive language on top. Items that actually move
the needle:

- [ ] **Optimization passes** — the C backend emits `-O3` builds; add
      dead-store elimination and copy-prop for the `s = scene_step(s, dt)`
      write-back pattern (currently copies whole structs every tick).
- [ ] **Struct-of-arrays option** — `scene.entities` is array-of-structs;
      an SoA variant (`pos_x: [f64]`, ...) would halve cache misses on
      big scenes. Offer as an alternative Scene layout.
- [ ] **Benchmark suite** — `vulcan bench` exists; add standard benchmarks
      (fib, nested loops, entity tick with 1000 entities) to track
      regressions, C vs JS vs Py.
- [ ] **Arena/scratch allocator via FFI** — for entity churn (spawn/reap
      per frame) a bump allocator in C beats Vec push/pop.
- [ ] **SIMD-friendly math** — Vec3 ops as separate x/y/z arrays opens
      auto-vectorization; keep the API, change the layout internally.

proprietary product) — it is vulcan's own engine, built in pure vulcan.

- [x] ~~Projectile entities~~ — DONE in v0.2 (`scene_fire_projectile`,
      swept-segment impact test so fast projectiles can't tunnel; fixed

      attack with `atan2`-style steering, aggro/attack ranges, fire

- [ ] **Raylib/SDL3 binding layer** — `lib/raylib.vulcan` with `extern "c"`

## Honest expectations (do not overpromise)

- "Better than Python and its ecosystem" is not a reachable milestone —
  Python has decades of libraries. Vulcan's real edge: native speed via C,
  one language across C/JS/Python backends, tiny readable output, and FFI
  into any C library. Compete on that.
- Unreal Engine is millions of lines of C++ built by hundreds of engineers
  over decades. The realistic goal is a capable vulcan-only engine with
  FFI to raylib/SDL for GPU rendering — not an Unreal clone.
- "Beat C++" in benchmarks: not literally — vulcan IS C underneath. The
  honest claim is C-grade performance with a much smaller, safer language.
  The performance items above (SoA, copy-prop, arenas) close the gap that
  vulcan's current codegen adds on top of C.
